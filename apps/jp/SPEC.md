# 日本語実装比較の共通仕様

`apps/nadesiko/` のなでしこ3 実装を、他の 17 言語で「識別子・テスト名・メッセージを日本語にして」書き直すための共通仕様です。
[第 9 章コラム](../../docs/article/integration/09-japanese-implementation-column.md) の検証用コードは、すべてこの仕様に従います。

## 基本方針

- 名前は **できる限り日本語** にする。言語仕様やツールが拒否した場合だけ回避策（ASCII 接頭辞、全角大文字など）を使い、拒否された事実（エラーメッセージ原文）を記録する。
- 名前はなでしこ3 の実装にそろえる（`FizzBuzz変換`・`タイプ生成`・`装飾` など）。言語の命名規則（大文字始まり・snake_case など）に合わせて変える場合は、その理由を記録する。
- テスト名はなでしこ3 のテスト名（`3を渡したらFizzを返す` など）を、その言語で表現できる最も文章に近い形で書く。
- 語順の再現（`3を FizzBuzz変換` のような SOV 順）を、その言語の正攻法（拡張メソッド、中置記法、パイプライン、演算子定義）で 1 つは試す。
- 各言語ディレクトリに `Makefile` を置き、`make test` でテストが走るようにする。

## 題材 A: FizzBuzz 変換（`src/fizzbuzz.nako3`）

| 関数 | 振る舞い |
|------|---------|
| `FizzBuzz変換(N)` | 15 の倍数で `FizzBuzz`、3 の倍数で `Fizz`、5 の倍数で `Buzz`、それ以外は数値の文字列 |
| `FizzBuzz配列作成(N)` | 1 から N までを `FizzBuzz変換` した配列 |

テスト（7 件）:

| テスト名 | 期待 |
|---------|------|
| 3を渡したらFizzを返す | `FizzBuzz変換(3)` = `Fizz` |
| 5を渡したらBuzzを返す | `FizzBuzz変換(5)` = `Buzz` |
| 15を渡したらFizzBuzzを返す | `FizzBuzz変換(15)` = `FizzBuzz` |
| 1を渡したら文字列1を返す | `FizzBuzz変換(1)` = `1` |
| 2を渡したら文字列2を返す | `FizzBuzz変換(2)` = `2` |
| 15まで作ると15件になる | `FizzBuzz配列作成(15)` の要素数 = 15 |
| 15まで作った配列の並び | `,` で結合すると `1,2,Fizz,4,Buzz,Fizz,7,8,Fizz,Buzz,11,Fizz,13,14,FizzBuzz` |

語順のテスト（1 件以上）: SOV 順の呼び出し（例: `3を FizzBuzz変換` に近い形）で `Fizz` が返ること。

## 題材 B: タイプ生成（`src/type.nako3`）

| 名前 | 振る舞い |
|------|---------|
| `タイプ`（型・クラス・構造体・辞書など） | `名前` と `変換`（数値 → 文字列の関数）を持つ |
| `タイプ生成(番号)` | 1 → 名前 `通常`・変換 `FizzBuzz変換`、2 → 名前 `数字限定`・変換は数値の文字列化のみ、3 → 名前 `FizzBuzz限定`・15 の倍数だけ `FizzBuzz` でそれ以外は数値の文字列。それ以外の番号はエラー `該当するタイプは存在しません: {番号}` |
| `タイプ変換(タイプ, N)` | タイプの変換を N に適用する |

型・列挙子・コンストラクタ・モジュールの名前も日本語を試す（言語が許せば `enum タイプ { 通常, 数字限定, FizzBuzz限定 }` なども可）。

テスト（5 件）:

| テスト名 | 期待 |
|---------|------|
| タイプ1は通常の変換をする | タイプ 1 で 3 → `Fizz`、名前 `通常` |
| タイプ2は数字だけを返す | タイプ 2 で 3 → `3`、名前 `数字限定` |
| タイプ3は15の倍数だけFizzBuzzを返す | タイプ 3 で 15 → `FizzBuzz` |
| タイプ3は3の倍数を数字で返す | タイプ 3 で 3 → `3` |
| 存在しないタイプはエラーになる | タイプ 4 でエラー。メッセージ `該当するタイプは存在しません: 4` |

## 題材 C: パイプライン（`src/pipeline.nako3`）

| 関数 | 振る舞い |
|------|---------|
| `装飾(文字列)` | `[文字列]` を返す |
| `FizzBuzz装飾(N)` | `FizzBuzz変換` してから `装飾` する（なでしこ3: `NをFizzBuzz変換して装飾して戻す`）。言語のパイプライン・合成・メソッドチェーンで「〜して〜して」の順を再現する |
| `パイプライン処理(N)` | 1 から N までを `FizzBuzz装飾` した配列 |

テスト（2 件）:

| テスト名 | 期待 |
|---------|------|
| 装飾すると角括弧で囲む | `装飾("Fizz")` = `[Fizz]` |
| 5までのパイプライン処理 | `パイプライン処理(5)` = `[1]`, `[2]`, `[Fizz]`, `[4]`, `[Buzz]` |

## 題材 D: 安全変換（`src/error.nako3`）

| 名前 | 振る舞い |
|------|---------|
| `変換結果`（Result 型・辞書など） | `成功`（値）と `失敗`（エラーメッセージ）を表す |
| `安全変換(N)` | 数値でなければ失敗 `数値を指定してください: {N}`、0 以下なら失敗 `正の数を指定してください: {N}`、それ以外は成功（`FizzBuzz変換(N)`） |

テスト（3 件、静的型付け言語は 2 件）:

| テスト名 | 期待 |
|---------|------|
| 正の数は成功になる | `安全変換(3)` が成功で値 `Fizz` |
| 0は失敗になる | `安全変換(0)` が失敗でメッセージ `正の数を指定してください: 0` |
| 数値でなければ失敗になる | `安全変換("a")` が失敗でメッセージ `数値を指定してください: a`（静的型付けで引数が数値型なら、コンパイル時に弾かれるため省略し、その事実を記録する） |

## 記録すること（`FINDINGS.md`）

各言語ディレクトリに `FINDINGS.md` を置き、以下を記録する。

1. 処理系・テストフレームワークのバージョン、`make test` の結果（件数）
2. 日本語にできた名前、できなかった名前と、そのときのエラー・警告メッセージの原文
3. 採用した回避策とその代償
4. 語順の再現方法（コード抜粋）
5. lint・formatter の反応（実行できた場合）
6. 日本語化スコア（各 0〜3 点）と根拠

| 軸 | 3 点 | 2 点 | 1 点 | 0 点 |
|----|------|------|------|------|
| 関数・変数名 | 制約なし | 軽微な制約（命名規則の警告など） | 一部の位置で不可 | 不可 |
| 型・モジュール名 | 型・列挙子・モジュール・ファイル名すべて可 | 一部に回避策が必要 | 大半に回避策が必要 | すべて ASCII 必須 |
| テスト名 | 空白・記号込みの文章で書ける | 識別子として日本語で書ける | ASCII 接頭辞などの制約付き | ASCII のみ |
| 語順の再現 | 助詞に相当する語を置いて SOV 順で書ける | パイプラインや後置呼び出しで SOV 順になる | 一部だけ SOV 順 | 前置の関数呼び出しのみ |
| ツール許容 | lint・formatter・テストランナーが設定変更なしで通る | 警告が出るが抑止できる | 抑止に大きな代償 | 動作しない |
