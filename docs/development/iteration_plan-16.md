## 設計メモ

### ディレクトリ構成（予定）

```
apps/nadesiko/
├── Makefile                                    (test / lint / format / doctest / check)
├── .gitignore
├── src/
│   ├── fizzbuzz.nako3                          (公開 API)
│   ├── type.nako3                              (タイプ別ディスパッチ)
│   ├── model.nako3                             (値オブジェクト・コレクション)
│   └── command.nako3                           (Command)
└── test/
    ├── fizzbuzz_test.nako3                     (コアテスト)
    ├── type_test.nako3                         (タイプテスト)
    └── command_test.nako3                      (コマンドテスト)

docs/article/
└── nadesiko/
    ├── index.md                                (なでしこ3 記事トップ)
    └── 01-todo-list-and-first-test.md ... 12-error-handling-and-type-safety.md (12 章)
```

章ファイル名は Python / Ruby と同じ命名に揃え、読み替えを行う第 7 章のみ `07-dictionary-dispatch-and-polymorphism.md` とする。

### なでしこ3 固有の特徴（12 章構成）

| 機能 | 章 | 内容 |
|------|-----|------|
| `●(Nを)関数名 … ここまで` | 1-3 | 助詞で引数を受ける関数定義 |
| `【A】と【B】がASSERT等` | 1-3 | 表明。不一致時に実行時エラー・終了コード 1 |
| `もし…ならば / 違えば、もし / 違えば` | 2-3 | 条件分岐（1 行形式も可） |
| `Iを1から100まで繰り返す` / `回` / `反復` | 3 | 繰り返し |
| `!「./lib.nako3」を取り込む` | 3, 9 | ファイル分割。取り込んだ関数は `ファイル名__関数名` で修飾される |
| `gonako lint` / `format` / `doctest` | 5-6 | 静的解析・整形・記事コードの出力照合 |
| 配列・辞書（`[..]` / `{"k":v}`） | 7-8 | データ表現、関数を値として格納したディスパッチ |
| `関数(x) … ここまで` | 10 | 無名関数 |
| `配列マップ` / `配列フィルタ` / `配列結合` | 10-11 | 高階命令とパイプライン的記述 |
| `エラー監視 … エラーならば … ここまで` / `エラー発生` | 12 | 例外処理 |

### 既存言語 → なでしこ3 対応マップ

| 既存言語の概念 | なでしこ3 での対応 |
|---------------|------------------|
| テストフレームワーク（assert） | `ASSERT等` + 自作 test runner |
| クラス / インスタンス | 辞書 + 生成関数 |
| インターフェース / ポリモーフィズム | 関数を格納した辞書によるディスパッチ |
| モジュール / パッケージ | `取り込む` と `ファイル名__` 名前空間 |
| ラムダ式 | `関数(x) … ここまで` |
| map / filter | `配列マップ` / `配列フィルタ` |
| try / catch / throw | `エラー監視` / `エラー発生` |

## Nix 環境

```
nix develop .#nadesiko
```

| パッケージ | 用途 |
|-----------|------|
| go | `gonako` のビルド（`go.mod` は Go 1.26 を要求） |
| gonako（`shellHook` でブートストラップ） | なでしこ3 の実行・lint・format・doctest |

nixpkgs に なでしこ3 のパッケージがあるかは未確認のため、Flix の `flix.jar` と同様に `shellHook` で `go install github.com/kujirahand/nadesiko3go/cmd/gonako@<固定コミット>` を実行する方式を第一候補とする。`go build ./...` は GUI 版（gtk / webkit2gtk 依存）で失敗するため、CLI 版（`cmd/gonako`）のみを導入する。

## IT1-IT15 からの学び（適用事項）

| 学び | IT16 での適用 |
|------|-------------|
| .gitignore を最初に作成する | ブートストラップしたバイナリ（`bin/` 等）を最初に除外 |
| Nix 環境を必ず使用する | `nix develop .#nadesiko` で全操作を実行 |
| CI は最初から Nix ベースで構築する | `nadesiko-ci.yml` を環境構築タスクに含める |
| 部ごとにコミットを分割する | 環境構築、第 1〜4 部ごとに `feat` / `docs` を分けてコミット |
| ランタイムの外部配布物はブートストラップする（Flix） | `gonako` を `shellHook` で導入しバージョン固定 |
| クラスを持たない言語の読み替え（Prolog） | 第 3 部を辞書・関数ディスパッチ・取り込みに読み替え |
| GitHub Issue の同期を忘れない | 着手時に US-017 の Issue を作成し、完了時にクローズ |

## リスクと対策

| リスク | 影響度 | 対策 |
|--------|--------|------|
| Go 版にテストランナーが無い | 中 | Makefile の test runner でファイル単位に実行し、終了コードで判定する |
| nixpkgs の Go が 1.26 未満 | 中 | `GOTOOLCHAIN=auto` を併用するか、リリースバイナリ取得方式に切り替える |
| Go 版が活発に開発中で挙動が変わる | 中 | 導入コミットを固定し、記事にバージョン（3.8.8）を明記する |
| 取り込みパスに `./` が必要、ループ内で `対象` が空になる等の癖 | 中 | 記事のコード例は実行確認済みのコードから転記し、`gonako doctest` で検証する |
| 一部の日本語識別子（`…倍にする` で終わる関数名など）が文法エラーになる | 低 | 関数名を実行確認してから記事に載せる |
| クラス構文を持たないため第 3 部が読者に分かりにくい | 中 | Python / Prolog との対応表を記事に含め、段階的に解説 |
