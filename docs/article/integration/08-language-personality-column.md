# コラム: 言語の性格を比喩で掴む

スコアや比較表は正確ですが、記憶には残りにくいものです。本章では各言語の「性格」を
掴むための比喩を 2 通り提示します。

| コラム | 見る観点 |
|--------|---------|
| 『Fate/stay night』で例える | クラスと強さ -- 性能・型の強さで並べる見方 |
| 『君のことが大大大大大好きな100人の彼女』で例える | 関係性 -- 優劣をつけず全てを等しく扱う見方 |

> **注意**: あくまで性格を掴むための比喩であり、技術的な優劣を示すものではありません。
> 対応づけの根拠は[トータルスコア](07-total-score-comparison.md)と各言語の特性に基づきますが、解釈は一つではありません。

## 『Fate/stay night』で例える

### 『Fate/stay night』を知らない方への前提

『Fate/stay night』は TYPE-MOON による伝奇ビジュアルノベル（2004 年発売）で、
のちにアニメ化・シリーズ化された作品です。公式サイトは
[Fate/stay night（TYPE-MOON）](https://www.typemoon.com/products/fate/index.html)
を参照してください。

物語は、願いを叶える「聖杯」を巡って 7 組が戦う**聖杯戦争**を舞台とします。
以下の用語だけ押さえれば、このコラムは読めます。

| 用語 | 意味 | このコラムでの読み替え |
|------|------|---------------------|
| サーヴァント | 過去の英雄が使い魔として召喚された存在 | プログラミング言語そのもの |
| マスター | サーヴァントと契約し使役する魔術師 | 言語を使う開発者 |
| クラス | サーヴァントの役割区分（セイバー、アーチャー、ランサー、ライダー、キャスター、バーサーカー、アサシンの 7 クラス） | 言語のパラダイムや得意領域 |
| 宝具 | サーヴァントが持つ切り札となる能力 | 言語固有の強力な機能 |
| 聖杯戦争 | 上記の 7 組による勝ち抜き戦 | 開発の現場（ただし言語同士は本来争いません） |

強いサーヴァントを召喚できても、マスターの力量が伴わなければ勝てない、という関係は
言語選択にもそのまま当てはまります。以下の対応づけはその前提で読んでください。

| 言語 | 対応 | 理由 |
|------|------|------|
| Java | セイバー（アルトリア） | 王道・規律・堅実。派手さより誠実さで、テスト基盤と開発環境が最も整う |
| Kotlin | セイバー・オルタ | 同じ聖剣（JVM）を握りながら、簡潔さと切れ味（null 安全・`when`）に振った現代の姿 |
| Scala | ギルガメッシュ | 王の財宝にあらゆる機能を所蔵。総合スコア 1 位だが、宝具を選べる者は限られる |
| Rust | アーチャー（エミヤ） | 「所有権」という鍛錬を経て堅牢に。コンパイラとの対話が日課 |
| Haskell | キャスター（メディア） | 純粋魔術＝型。詠唱（型注釈）の段階でほぼ勝敗が決している |
| Flix | ルーラー（ジャンヌ） | 効果システムで副作用を「裁定」する新クラス。型と効果の両方に権能を持つ |
| Prolog | 遠坂臓硯 | 古く、独自の理屈（単一化とバックトラッキング）で現代の常識の外に立つ |
| TypeScript | 遠坂凛 | 素地（JavaScript）を宝石魔術（型）で強化する器用な実務家 |
| Python | 衛宮士郎 | 誰でも握れる主人公枠。才ではなく積み上げ（テスト）で押し切る |
| Ruby | ライダー（メデューサ） | 書き心地がとにかく優しい。手綱を預けると気持ちよく走る |
| Go | ランサー（クー・フーリン） | 速く実直、槍一本（goroutine）で戦う。小細工がないのが強み |
| F# | アサシン（佐々木小次郎） | 燕返し＝網羅性のある一刀。控えめだが技は最上位（総合 2 位） |
| C# | 言峰綺礼 | 巨大な組織（.NET）を背景にした隙のない実務。裏で全部揃っている |
| Elixir | バーサーカー（ヘラクレス） | 十二の試練＝スーパーバイザによる復活。倒れても立ち上がる |
| Clojure | イリヤスフィール | 千年の錬金術（Lisp の系譜）。小柄な構文に膨大な魔力（マクロ）を宿す |
| PHP | 間桐桜 | 長く軽んじられてきたが、Web の大半を支える力を内に持ち、8.x で本領を見せた |

### スコアとの対応

- **総合上位**（Scala 17.2 / F# 17.1 / Haskell 16.6）は最上位クラスの枠。ただし
  扱う側（マスター）の力量を要求します
- **バランス型**（Rust・Kotlin 16.3）は、長く戦線を維持できる現実的な布陣です
- **主人公枠**（Python・TypeScript）はスコアよりも「誰でも戦線に立てる」ことが価値です
- **最下位の Prolog 10.1** は弱いのではなく、そもそも別の戦い（論理と探索）を
  戦っています。評価軸の外にいる言語がある、という事実そのものがこの比喩の要点です

学習順序に迷ったときは、「いま自分はどのクラスを引きたいのか」で選ぶのも一つの手です。
堅実な基盤なら Java、鋭さなら Kotlin や F#、理論の極致なら Haskell や Flix、
常識の外を見たいなら Prolog です。

## 100 人の彼女で例える

### 『君のことが大大大大大好きな100人の彼女』を知らない方への前提

原作: 中村力斗、作画: 野澤ゆき子による漫画で、『週刊ヤングジャンプ』（集英社）にて
2020 年から連載中の作品です。詳細は
[Wikipedia の作品記事](https://ja.wikipedia.org/wiki/%E5%90%9B%E3%81%AE%E3%81%93%E3%81%A8%E3%81%8C%E5%A4%A7%E5%A4%A7%E5%A4%A7%E5%A4%A7%E5%A4%A7%E5%A5%BD%E3%81%8D%E3%81%AA100%E4%BA%BA%E3%81%AE%E5%BD%BC%E5%A5%B3)
を参照してください。

主人公は「運命の相手が 100 人いる」と神から告げられ、しかも付き合わなければ相手が
死んでしまうという宿命を負い、100 人全員と同時に、全員を平等に愛するという選択を
します。**誰か一人を選ばない**というこの構えは、「最強の言語を一つ選ぶ」ことをせず
16 言語すべてを同じ FizzBuzz で扱う本シリーズの立場そのものです。

### 対応づけ（加入順）

| 言語 | 対応 | 理由 |
|------|------|------|
| 開発者（読者） | 愛城恋太郎 | 全員を平等に愛し、誰も切り捨てない。本シリーズを読み進める立場 |
| Java | 花園羽香里 | 最初の彼女。計算高いが気配りができる＝堅実で王道、隙のない基盤 |
| Rust | 院田唐音 | ツンデレでツッコミ役。借用チェッカに叱られ続けるが、言うことは全部正しい |
| Haskell | 好本静 | 自分の声で話すのが苦手で読み上げアプリ越しに伝える＝記述量が極小で、型を介して意図を語る |
| F# | 栄逢凪乃 | 学業優秀でクール、効率優先。派手さはないが総合 2 位の優等生 |
| Elixir | 薬膳楠莉 | 不老不死の薬。何度倒れてもスーパーバイザが起こす耐障害性そのもの |
| Kotlin | 花園羽々里 | 羽香里の母＝同じ花園家（JVM 一族）。資産を受け継ぎつつ新しい書き方を好む |
| Python | 銘戸芽衣 | メイドで「尽くすことを信条」。初学者の面倒を全部見てくれる |
| Go | 須藤育 | ストイックで痛みを伴う運動を好む。冗長な `if err != nil` を黙々と書く美学 |
| Scala | 美杉美々美 | 「自分が世界一美しい」と信じる自己肯定力＝総合 1 位の高機能 |
| Clojure | 華暮愛々 | 恥ずかしがりで編み物が得意。括弧の中にマクロを編み込み、姿は目立たない |
| Flix | 伊院知与 | 委員長気質で責任感が強い。効果システムで副作用を監督・管理する |
| TypeScript | ナディー（大和撫子） | 本名は純日本人（JavaScript）だが憧れてブロンドに染めた＝中身はそのままで型に装いを変えた |
| C# | 優敷山女 | 200cm 超の巨躯で心優しい。.NET の圧倒的な物量と面倒見の良さ |
| PHP | 薬膳ヤク | 89 歳ながら幼い姿で戦場経験あり、運動能力が高い＝歴史が長く、8.x の JIT で今も速い現役 |
| Ruby | 毛樽井亜愛子衣 | 「人と同じ気持ちになること」が好きなギャル。開発者の気持ちに寄り添う書き心地 |
| Prolog | 中二詩人 | 吟遊詩人の持って回った言い回し＝述語で世界を語る宣言的スタイル |

番外として、原賀胡桃（食欲旺盛で常に食べ物のことを考えている）は JVM 系のメモリ消費枠
です。空腹（ヒープ不足）でイライラするところまで一致します。

### 2 つのコラムの違い

| | Fate/stay night 版 | 100 人の彼女 版 |
|--|-------------------|----------------|
| 見る観点 | クラスと強さ | 関係性 |
| スコアとの関係 | 上位＝最上位クラスとして扱う | スコアの高低を問わず等価に扱う |
| 示したいこと | 言語ごとの得意分野と限界 | 優劣をつけずに全てを学ぶ意味 |

トータルスコア 1 位の Scala（17.2）も最下位の Prolog（10.1）も、恋太郎の基準では
同じ重みで愛されます。これは[第 7 章](07-total-score-comparison.md)で述べた
「スコアは領域のカバー範囲であって優劣ではない」という注記と、同じことを別の角度から
言っているにすぎません。
