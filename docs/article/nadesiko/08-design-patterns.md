# 第 8 章: デザインパターンの適用

## 8.1 はじめに

前章では、関数を格納した辞書をタイプとみなし、`タイプ変換` が辞書の `変換` を呼ぶだけで振る舞いを切り替えられるようにしました。この章では、同じ「辞書 + 関数」の組み合わせで、さらにいくつかの **デザインパターン** を適用します。

オブジェクト指向言語では、値オブジェクトやコマンドを「クラスのインスタンス」として表現します。クラス構文のないなでしこ3 では、次のように読み替えます。

| パターン | オブジェクト指向での表現 | なでしこ3 での表現 |
|----------|--------------------------|--------------------|
| Value Object | 不変のクラス + `equals` | 辞書 + 生成関数・取得関数・等価判定関数 |
| First-Class Collection | リストを包むクラス | `{"一覧": 配列}` を包む辞書 + 専用関数 |
| Command | `execute` を持つインターフェース | `実行` キーに関数を持つ辞書 |

データの形（辞書のキー）を直接触る処理は、それぞれのファイルの関数の中だけに閉じ込めます。呼び出し側は関数だけを使い、辞書のキーを知らなくて済むようにする。これが、クラスのない言語での **カプセル化** です。

## 8.2 値オブジェクト（Value Object）

### 問題: 数値と変換結果がばらばら

`タイプ変換` は変換後の文字列だけを返します。「3 を変換したら Fizz になった」という一組の事実を扱うには、数値と結果を別々の変数で持ち回ることになり、両者の対応がコード上のどこにも表れません。そこで、数値と変換結果を 1 つの値にまとめます。

### Red: 値オブジェクトのテスト

`test/value_test.nako3` を作ります。

```nako3
!「./helper.nako3」を取り込む
!「../src/value.nako3」を取り込む

通常 = 1からタイプ生成
値 = 通常で3からFizzBuzz値作成

「値オブジェクトは数値を持つ」と(値の数値取得)と3で検証
「値オブジェクトは変換結果を持つ」と(値の文字列取得)と「Fizz」で検証
テスト結果報告
```

`src/value.nako3` には、まだ `type.nako3` の取り込みしかありません。

```bash
$ gonako run test/value_test.nako3
[文法エラー]test/value_test.nako3(5行目): 未解決の単語があります: [単語『value_test__通常』で,数値3から]
次の命令の可能性があります:

```

`FizzBuzz値作成` が存在しないので文法エラーです（Red）。エラーメッセージに出ている `value_test__通常` は、テストファイルの変数 `通常` の内部名です。取り込みと名前空間の仕組みは第 9 章で扱います。

### Green: 生成関数と取得関数

```nako3
# 値オブジェクト（数値と変換結果の組）
!「./type.nako3」を取り込む

●(タイプでNから)FizzBuzz値作成
    {"数値": N, "値": (タイプでNをタイプ変換)}を戻す
ここまで

●(値の)数値取得
    値["数値"]を戻す
ここまで

●(値の)文字列取得
    値["値"]を戻す
ここまで
```

```bash
$ gonako run test/value_test.nako3
  ok: 値オブジェクトは数値を持つ
  ok: 値オブジェクトは変換結果を持つ
  2件成功、0件失敗
```

- `FizzBuzz値作成` が **生成関数**（コンストラクタに相当）、`数値取得`・`文字列取得` が **取得関数**（getter に相当）です。辞書のキー `"数値"`・`"値"` を知っているのはこのファイルだけです。
- `●(値の)数値取得` の助詞 `の` により、呼び出しは `値の数値取得` と「値の数値を取得」と読める形になります。関数名には `の` を含められませんが（第 7 章）、**引数の助詞** としてなら使えます。
- 辞書リテラルの中で関数を呼ぶときは `(タイプでNをタイプ変換)` のように括弧で囲み、どこまでが 1 つの式かを明示します。
- なでしこ3 の辞書には書き換えを禁止する仕組みがありません。値オブジェクトの **不変性** は「生成後に辞書を書き換えない」という約束で守ります。書き換える関数を用意しないことで、その約束をコードの形にしています。

### Red: 等価判定

値オブジェクトは、同じ数値と同じ結果を持てば等しいとみなしたい値です。まず、辞書をそのまま `=` で比べるとどうなるかをテストで確かめます（学習用テスト）。

```nako3
「同じ中身の辞書は = で等しい」と(値 = (通常で3からFizzBuzz値作成))と(はい)で検証
```

```bash
$ gonako run test/eq_test.nako3
  NG: 同じ中身の辞書は = で等しい: ASSERT失敗: 『false』と『true』が一致しません。
  0件成功、1件失敗
[実行時エラー]test/eq_test.nako3(20行目): 1件のテストが失敗しました
```

中身が同じでも、別々に作った辞書は `=` では等しくなりません。辞書の `=` は **同じ辞書そのものかどうか**（参照の同一性）を比べるからです。したがって、中身で比べる **等価判定関数** が必要です。

`はい` を `(はい)` と括弧で囲んでいるのは、`「…」とはいで検証` と書くと `とは` がひとかたまりに読まれてしまうためです。

等価判定のテストを値オブジェクトのテストに加えます。

```nako3
「同じ数値と結果なら等価」と(値と(通常で3からFizzBuzz値作成)がFizzBuzz値等価)と(はい)で検証
「数値が違えば等価でない」と(値と(通常で6からFizzBuzz値作成)がFizzBuzz値等価)と(いいえ)で検証
```

```bash
$ gonako run test/value_test.nako3
  ok: 値オブジェクトは数値を持つ
  ok: 値オブジェクトは変換結果を持つ
  NG: 同じ数値と結果なら等価: ASSERT失敗: 『undefined』と『boolean』が一致しません。
  NG: 数値が違えば等価でない: ASSERT失敗: 『undefined』と『boolean』が一致しません。
  2件成功、2件失敗
[実行時エラー]test/value_test.nako3(20行目): 2件のテストが失敗しました
```

`FizzBuzz値等価` がまだないので、結果の型が `undefined` になり、テスト補助の型の比較で失敗しています（Red）。第 2 章でテスト補助に型の比較を入れておいたおかげで、何が起きているかがはっきり分かります。

### Green: FizzBuzz値等価

```nako3
●(値Aと値Bが)FizzBuzz値等価
    (値A["数値"] = 値B["数値"]) かつ (値A["値"] = 値B["値"])を戻す
ここまで
```

```bash
$ gonako run test/value_test.nako3
  ok: 値オブジェクトは数値を持つ
  ok: 値オブジェクトは変換結果を持つ
  ok: 同じ数値と結果なら等価
  ok: 数値が違えば等価でない
  4件成功、0件失敗
```

`●(値Aと値Bが)FizzBuzz値等価` は「値A と 値B が FizzBuzz 値として等価」と読めます。`かつ` で 2 つの比較をつなぎ、真偽値（`はい`／`いいえ`）を返します。

| 特徴 | 実現方法（なでしこ3） |
|------|-----------------------|
| 生成の集約 | `FizzBuzz値作成` |
| 要素の取り出し | `数値取得` / `文字列取得` |
| 等価性 | `FizzBuzz値等価`（`=` は参照の比較なので自作する） |
| 不変性 | 書き換える関数を用意しない（約束） |

## 8.3 ファーストクラスコレクション（First-Class Collection）

### 問題: 生の配列の直接操作

値オブジェクトの配列をそのまま扱うと、「件数を数える」「文字列だけを取り出す」といった操作が呼び出し側に散らばります。そこで配列を辞書 `{"一覧": 配列}` で包み、操作を専用の関数に集めます。

### Red

`src/list.nako3` を作り（まだ `value.nako3` の取り込みだけ）、`test/value_test.nako3` の取り込み先を `../src/list.nako3` に変えて、リストのテストを追加します。

```nako3
リスト = 通常で15までFizzBuzzリスト作成
「リストの件数は15」と(リストの件数取得)と15で検証
「リストの文字列一覧」と(リストの文字列一覧取得を「,」で配列結合)と「1,2,Fizz,4,Buzz,Fizz,7,8,Fizz,Buzz,11,Fizz,13,14,FizzBuzz」で検証
```

```bash
$ gonako run test/value_test.nako3
[文法エラー]test/value_test.nako3(12行目): 未解決の単語があります: [単語『value_test__通常』で,数値15まで]
次の命令の可能性があります:

```

### Green

```nako3
# ファーストクラスコレクション（値オブジェクトの一覧を包む）
!「./value.nako3」を取り込む

●(タイプでNまで)FizzBuzzリスト作成
    一覧 = []
    Iを1からNまで繰り返す
        一覧に(タイプでIからFizzBuzz値作成)を配列追加
    ここまで
    {"一覧": 一覧}を戻す
ここまで

●(リストの)件数取得
    リスト["一覧"]の配列要素数を戻す
ここまで

●(リストの)文字列一覧取得
    結果 = []
    要素でリスト["一覧"]を反復
        結果に(要素の文字列取得)を配列追加
    ここまで
    結果を戻す
ここまで
```

```bash
$ gonako run test/value_test.nako3
  ok: 値オブジェクトは数値を持つ
  ok: 値オブジェクトは変換結果を持つ
  ok: 同じ数値と結果なら等価
  ok: 数値が違えば等価でない
  ok: リストの件数は15
  ok: リストの文字列一覧
  6件成功、0件失敗
```

- `Iを1からNまで繰り返す` で 1 から N までを数え、`配列追加` で値オブジェクトを 1 つずつ加えます。
- `要素でリスト["一覧"]を反復` は、配列の各要素を変数 `要素` に入れて繰り返します。値オブジェクトの中身には `文字列取得` を通してアクセスし、キー `"値"` を直接触りません。
- `リスト` のキー `"一覧"` を知っているのは `list.nako3` の関数だけです。呼び出し側は `件数取得` と `文字列一覧取得` だけを使います。

## 8.4 コマンドパターン（Command）

### 問題: 操作の使い分け

「1 つの値を作る」と「1 から N までのリストを作る」という 2 種類の操作を、呼び出し側が関数名で使い分けるのは煩雑です。操作そのものを値にしておけば、「何をするか」を決める場所と「実行する」場所を分けられます。

### 解決: 「実行」関数を持つ辞書

コマンドを、キー `実行` に関数を持つ辞書として表します。関数は **無名関数** `関数(N) … ここまで` で作り、作成時に渡されたタイプを **クロージャ** として捕捉させます。

### Red: 値コマンドのテスト

```nako3
!「./helper.nako3」を取り込む
!「../src/command.nako3」を取り込む

通常 = 1からタイプ生成

値コマンド = 通常で値コマンド作成
結果 = 値コマンドで5をコマンド実行
「値コマンドは1件の値を返す」と(結果の配列要素数)と1で検証
「値コマンドの値はBuzz」と(結果[0]の文字列取得)と「Buzz」で検証
テスト結果報告
```

```bash
$ gonako run test/command_test.nako3
[文法エラー]test/command_test.nako3(6行目): 未解決の単語があります: [単語『command_test__通常』で]
次の命令の可能性があります:

```

### 「実行」という変数名は使えない

最初は、無名関数を `実行` という変数に入れてから辞書に詰めようとしました。

```nako3
●(タイプで)値コマンド作成
    実行 = 関数(N)
        [タイプでNからFizzBuzz値作成]を戻す
    ここまで
    {"名前": "値コマンド", "実行": 実行}を戻す
ここまで
```

```bash
$ gonako lint src/command.nako3
[文法エラー]src/command.nako3(4行目): 関数『command__値コマンド作成』の定義で以下のエラーがありました。
[文法エラー]src/command.nako3(5行目): 関数『実行』に代入できません。
```

`実行` はなでしこ3 の **組み込み命令** の名前なので、変数として代入できません。辞書のキー `"実行"` は文字列なので問題ありませんが、変数名は `処理` に変えます。

### Green

```nako3
●(タイプで)値コマンド作成
    処理 = 関数(N)
        [タイプでNからFizzBuzz値作成]を戻す
    ここまで
    {"名前": "値コマンド", "実行": 処理}を戻す
ここまで

●(コマンドでNを)コマンド実行
    処理 = コマンド["実行"]
    処理(N)を戻す
ここまで
```

```bash
$ gonako run test/command_test.nako3
  ok: 値コマンドは1件の値を返す
  ok: 値コマンドの値はBuzz
  2件成功、0件失敗
```

- `関数(N) … ここまで` は名前のない関数（無名関数）です。本体の中の `タイプ` は `値コマンド作成` の引数で、無名関数はそれを覚えたまま外へ持ち出されます（クロージャ）。コマンドを実行するときにタイプを渡し直す必要はありません。
- 値コマンドの結果を `[…]` で 1 要素の配列にしているのは、次に作るリストコマンドと **戻り値の形をそろえる** ためです。どちらのコマンドも「値オブジェクトの配列」を返すので、呼び出し側は結果を同じように扱えます。
- `コマンド実行` は、第 7 章の `タイプ変換` と同じく、辞書から関数を取り出して呼ぶだけです。どのコマンドかは判定しません。

### Red → Green: リストコマンド

テストにリストコマンドの検証を追加します。

```nako3
リストコマンド = 通常でリストコマンド作成
結果 = リストコマンドで5をコマンド実行
「リストコマンドは5件の値を返す」と(結果の配列要素数)と5で検証
「リストコマンドの最後の値はBuzz」と(結果[4]の文字列取得)と「Buzz」で検証
「コマンドは名前を持つ」とリストコマンド["名前"]と「リストコマンド」で検証
```

```bash
$ gonako run test/command_test.nako3
[文法エラー]test/command_test.nako3(11行目): 未解決の単語があります: [単語『command_test__通常』で]
次の命令の可能性があります:

```

リストコマンドは `FizzBuzzリスト作成` に委譲し、コレクションの中の配列を返します。

```nako3
●(タイプで)リストコマンド作成
    処理 = 関数(N)
        (タイプでNまでFizzBuzzリスト作成)["一覧"]を戻す
    ここまで
    {"名前": "リストコマンド", "実行": 処理}を戻す
ここまで
```

```bash
$ gonako run test/command_test.nako3
  ok: 値コマンドは1件の値を返す
  ok: 値コマンドの値はBuzz
  ok: リストコマンドは5件の値を返す
  ok: リストコマンドの最後の値はBuzz
  ok: コマンドは名前を持つ
  5件成功、0件失敗
```

## 8.5 適用したデザインパターン一覧

| パターン | 実装 | 役割 |
|----------|------|------|
| Strategy（第 7 章） | `変換` 関数を持つタイプの辞書 + `タイプ変換` | 変換ルールの切り替え |
| Factory Method（第 7 章） | `タイプ生成` | 番号からタイプを作る（未定義は `エラー発生`） |
| Value Object | `FizzBuzz値作成` / `数値取得` / `文字列取得` / `FizzBuzz値等価` | 数値と変換結果の組を表す |
| First-Class Collection | `FizzBuzzリスト作成` / `件数取得` / `文字列一覧取得` | 値の一覧の操作を集約 |
| Command | `実行` 関数を持つ辞書 + `コマンド実行` | 操作を値にする |

## 8.6 各言語のデザインパターン比較

| パターン | なでしこ3 | Python | Prolog |
|----------|-----------|--------|--------|
| Value Object | 辞書 + 取得関数 + 等価判定関数 | `__eq__` を持つクラス | 複合項 |
| 等価性 | 自作の `FizzBuzz値等価` | `__eq__` | `==` による構造比較 |
| Collection | `{"一覧": 配列}` + 専用関数 | リストを包むクラス | 専用モジュール |
| Command | `実行` 関数を持つ辞書（クロージャ） | `execute` を持つクラス | 項 + `execute/3` の複数節 |

## 8.7 まとめ

この章で学んだこと。

1. **値オブジェクト**: 辞書に生成関数・取得関数・等価判定関数を添えて、数値と変換結果の組を表した。辞書の `=` は参照の比較なので、中身の比較は自作する
2. **ファーストクラスコレクション**: 値オブジェクトの配列を `{"一覧": 配列}` で包み、件数取得と文字列一覧取得を専用関数に集めた
3. **コマンドパターン**: 無名関数とクロージャで、タイプを覚えた `実行` 関数を作り、辞書に格納した。`実行` は組み込み命令なので変数名には使えず、`処理` にした
4. **カプセル化の読み替え**: 辞書のキーを知っているのは、その辞書を作るファイルの関数だけにした

次の章では、SOLID 原則の観点からここまでのコードを検証し、ファイル単位のモジュール構成と依存の向きを整理します。

```nako3
●(タイプで)値コマンド作成
    処理 = 関数(N)
        [タイプでNからFizzBuzz値作成]を戻す
    ここまで
    {"名前": "値コマンド", "実行": 処理}を戻す
ここまで

●(タイプで)リストコマンド作成
    処理 = 関数(N)
        (タイプでNまでFizzBuzzリスト作成)["一覧"]を戻す
    ここまで
    {"名前": "リストコマンド", "実行": 処理}を戻す
ここまで

●(コマンドでNを)コマンド実行
    処理 = コマンド["実行"]
    処理(N)を戻す
ここまで
```

```nako3
!「./helper.nako3」を取り込む
!「../src/list.nako3」を取り込む

通常 = 1からタイプ生成
値 = 通常で3からFizzBuzz値作成

「値オブジェクトは数値を持つ」と(値の数値取得)と3で検証
「値オブジェクトは変換結果を持つ」と(値の文字列取得)と「Fizz」で検証
「同じ数値と結果なら等価」と(値と(通常で3からFizzBuzz値作成)がFizzBuzz値等価)と(はい)で検証
「数値が違えば等価でない」と(値と(通常で6からFizzBuzz値作成)がFizzBuzz値等価)と(いいえ)で検証

リスト = 通常で15までFizzBuzzリスト作成
「リストの件数は15」と(リストの件数取得)と15で検証
「リストの文字列一覧」と(リストの文字列一覧取得を「,」で配列結合)と「1,2,Fizz,4,Buzz,Fizz,7,8,Fizz,Buzz,11,Fizz,13,14,FizzBuzz」で検証
```
