# 第 7 章: 辞書と関数によるポリモーフィズム

## 7.1 はじめに

第 1 部では FizzBuzz を TDD で実装し、第 2 部では開発環境を整備しました。第 3 部では **構造化設計** に踏み込み、手続き的なコードをより柔軟で拡張しやすい構造にリファクタリングしていきます。

この章では、**追加仕様** を題材にして **ポリモーフィズム** を学びます。オブジェクト指向言語ではサブクラスやインターフェースで条件分岐を型の階層に置き換えます。しかし、なでしこ3（Go 版 `gonako`）には **クラス構文がありません**。Prolog 版が複数節ディスパッチで同じ効果を得たように、なでしこ3 では **関数を値として格納した辞書** を「オブジェクト」とみなし、辞書から取り出した関数を呼ぶことで振る舞いを切り替えます。

| オブジェクト指向の概念 | なでしこ3 での読み替え |
|------------------------|------------------------|
| クラスのインスタンス | 辞書 `{"名前": …, "変換": …}` |
| メソッド | 辞書に格納した関数（`{関数}関数名`） |
| 仮想メソッド呼び出し | 辞書から関数を取り出して呼ぶ（`タイプ変換`） |
| ファクトリメソッド | 番号から辞書を作る関数（`タイプ生成`） |
| 例外 | `エラー発生` / `エラー監視` |

## 7.2 追加仕様

FizzBuzz に 3 つの **タイプ** を導入します。

```
タイプごとに出力を切り替えることができる。
タイプ 1 は通常の FizzBuzz、タイプ 2 は数字のみ、タイプ 3 は FizzBuzz の場合のみをプリントする。
```

| タイプ | 名前 | 仕様 |
|--------|------|------|
| タイプ 1 | 通常 | 3 の倍数→Fizz、5 の倍数→Buzz、15 の倍数→FizzBuzz、それ以外→数値 |
| タイプ 2 | 数字限定 | すべて数値の文字列を返す（Fizz/Buzz 変換なし） |
| タイプ 3 | FizzBuzz限定 | 15 の倍数→FizzBuzz、それ以外→数値 |

## 7.3 手続き的なアプローチ

最初に思いつくのは、タイプ番号で条件分岐する手続き的なアプローチです。

```nako3
!「./src/fizzbuzz.nako3」を取り込む

●(タイプでNを)手続き変換
    もし、タイプ = 1ならば
        NをFizzBuzz変換して戻す
    違えば、もし、タイプ = 2ならば
        Nを文字列変換して戻す
    違えば、もし、タイプ = 3ならば
        もし、N % 15 = 0ならば,「FizzBuzz」を戻す
        Nを文字列変換して戻す
    ここまで
    「該当するタイプは存在しません: {タイプ}」のエラー発生
ここまで

(1で3を手続き変換)を表示
(2で3を手続き変換)を表示
(3で15を手続き変換)を表示
```

```bash
$ gonako run proc.nako3
Fizz
3
FizzBuzz
```

動きはしますが、この実装には問題があります。

- **単一責任原則の違反**: 1 つの関数に 3 種類の変換ルールが詰め込まれている
- **開放閉鎖原則の違反**: 新しいタイプを追加するたびに、この `もし … 違えば、もし …` の連鎖を修正する必要がある
- **呼び出し側への漏れ**: 呼び出すたびにタイプ番号を渡すので、「番号の意味」を呼び出し側がいつも意識する

そこで、タイプごとの変換ルールを **別々の関数** に分け、「どの関数を使うか」をタイプそのもの（辞書）に持たせます。

## 7.4 ポリモーフィズム — 辞書に関数を入れる

### 関数を値として扱う

なでしこ3 では、関数名の前に `{関数}` を付けると、関数を呼び出さずに **値として取り出せます**。取り出した関数は変数や辞書に入れておき、あとから `変数(引数)` の形で呼び出せます。

```nako3
タイプ = {"名前": "通常", "変換": {関数}FizzBuzz変換}
```

この辞書が「タイプ 1 のオブジェクト」です。`名前` が属性、`変換` がメソッドに当たります。`{関数}` を付けずに `"変換": FizzBuzz変換` と書くと、関数名は値として扱われず、辞書の宣言そのものが文法エラーになります。

```bash
$ gonako run inline2.nako3
[文法エラー]inline2.nako3(2行目): 単語『タイプ』への代入文で計算式に以下の書き間違いがあります。
[文法エラー]inline2.nako3(2行目): 辞書オブジェクトの宣言で値がありません。
```

### Red: タイプ 1 のテスト

`test/type_test.nako3` を作り、第 2 章のテスト補助 `検証` を使ってタイプ 1 のテストを書きます。

```nako3
!「./helper.nako3」を取り込む
!「../src/type.nako3」を取り込む

通常 = 1からタイプ生成

「タイプ1の名前は通常」と通常["名前"]と「通常」で検証
「タイプ1は3をFizzに変換する」と(通常で3をタイプ変換)と「Fizz」で検証
「タイプ1は15をFizzBuzzに変換する」と(通常で15をタイプ変換)と「FizzBuzz」で検証
テスト結果報告
```

`src/type.nako3` には、まだ `fizzbuzz.nako3` の取り込みしか書いていません。

```bash
$ gonako run test/type_test.nako3
[文法エラー]test/type_test.nako3(4行目): 未解決の単語があります: [数値1から]
次の命令の可能性があります:

```

`タイプ生成` という関数が存在しないため、`1から` の続きを解釈できずに文法エラーになります（Red）。なでしこ3 は助詞で引数を区切るので、未定義の関数は「助詞付きの値が余っている」という形で報告されます。

### Green: 関数を格納した辞書を返す

```nako3
# タイプ別の変換（関数を格納した辞書によるポリモーフィズム）
!「./fizzbuzz.nako3」を取り込む

●(番号から)タイプ生成
    {"名前": "通常", "変換": {関数}FizzBuzz変換}を戻す
ここまで

●(タイプでNを)タイプ変換
    変換 = タイプ["変換"]
    変換(N)を戻す
ここまで
```

```bash
$ gonako run test/type_test.nako3
  ok: タイプ1の名前は通常
  ok: タイプ1は3をFizzに変換する
  ok: タイプ1は15をFizzBuzzに変換する
  3件成功、0件失敗
```

`タイプ生成` はまだ番号を見ずにタイプ 1 を返す仮実装です。なでしこ3 固有の書き方を確認しましょう。

- `●(タイプでNを)タイプ変換` の `で`・`を` は **助詞による引数** です。呼び出し側も定義に合わせて `通常で3をタイプ変換` と書きます。日本語として「通常（のタイプ）で 3 をタイプ変換する」と読めるのが、なでしこ3 らしいところです。
- `タイプ変換` は、渡された辞書の `変換` に入っている関数を取り出して呼ぶだけです。どのタイプかを **一切判定していません**。これが **ポリモーフィズム** です。呼び出し側は「`変換` を持つ辞書」でさえあれば、どのタイプでも同じ `タイプ変換` で扱えます。なでしこ3 は動的型付けなので、Ruby や Python のダックタイピングに近い考え方です。
- 辞書から取り出した関数は、一度変数 `変換` に受けてから `変換(N)` と呼んでいます。`タイプ["変換"](3)` のように取り出しと呼び出しを 1 つの式に書くと、gonako では解析できません。

```bash
$ gonako run inline.nako3
[文法エラー]inline.nako3(3行目): (...)の解析エラー。『inline__タイプ』の近く
```

### 「数字のみ変換」が壊れる

タイプ 2 用の変換関数を追加し、`タイプ生成` で番号によって返す辞書を切り替えます。関数名は素直に `数字のみ変換` としてみました。

```nako3
●(Nを)数字のみ変換
    Nを文字列変換して戻す
ここまで

●(番号から)タイプ生成
    もし、番号 = 1ならば
        {"名前": "通常", "変換": {関数}FizzBuzz変換}を戻す
    違えば、もし、番号 = 2ならば
        {"名前": "数字のみ", "変換": {関数}数字のみ変換}を戻す
    ここまで
ここまで
```

```bash
$ gonako lint src/type.nako3
[文法エラー]src/type.nako3(4行目): 関数『type__数字』の定義で以下のエラーがありました。
[文法エラー]src/type.nako3(4行目): 不完全な文です。単語『み変換』が解決していません。
```

関数名が `数字` と `み変換` に分かれてしまいました。なでしこ3 は **ひらがなを助詞の手がかりにして** 単語を区切ります。`数字のみ変換` の `の` が助詞「の」と解釈され、関数名は `数字` で終わったものと見なされたのです。英語圏の言語で識別子に空白を入れられないのと同じく、なでしこ3 では **識別子にひらがな（特に助詞になる文字）を含めない** のが安全です。

## 7.7 未定義のタイプはエラー

### Red: エラー監視でエラーを捕まえるテスト

前節で見たとおり、未定義の番号を渡すと `タイプ生成` は黙って空文字列を返し、ずっと後の `タイプ変換` で分かりにくいエラーになります。問題の原因に近い場所で失敗させるため、未定義の番号では **エラーを発生** させることにします。テストでは `エラー監視 … エラーならば … ここまで` でエラーを捕まえ、`エラーメッセージ` を検証します。

```nako3
メッセージ = 「」
エラー監視
    4からタイプ生成
エラーならば
    メッセージ = エラーメッセージ
ここまで
「未定義のタイプはエラーになる」とメッセージと「該当するタイプは存在しません: 4」で検証
テスト結果報告
```

```bash
$ gonako run test/type_test.nako3
  ok: タイプ1の名前は通常
  ok: タイプ1は3をFizzに変換する
  ok: タイプ1は15をFizzBuzzに変換する
  ok: タイプ2は3を数字のまま返す
  ok: タイプ2は15を数字のまま返す
  ok: タイプ3は3を数字のまま返す
  ok: タイプ3は5を数字のまま返す
  ok: タイプ3は15をFizzBuzzに変換する
  NG: 未定義のタイプはエラーになる: ASSERT失敗: 『』と『該当するタイプは存在しません: 4』が一致しません。
  8件成功、1件失敗
[実行時エラー]test/type_test.nako3(20行目): 1件のテストが失敗しました
```

エラーが起きないので `メッセージ` は初期値の `「」` のままです（Red）。

### Green: エラー発生

`タイプ生成` の最後、どの分岐にも当てはまらなかったときに `エラー発生` を置きます。

```nako3
●(番号から)タイプ生成
    もし、番号 = 1ならば
        {"名前": "通常", "変換": {関数}FizzBuzz変換}を戻す
    違えば、もし、番号 = 2ならば
        {"名前": "数字限定", "変換": {関数}数字限定変換}を戻す
    違えば、もし、番号 = 3ならば
        {"名前": "FizzBuzz限定", "変換": {関数}FizzBuzz限定変換}を戻す
    ここまで
    「該当するタイプは存在しません: {番号}」のエラー発生
ここまで
```

```bash
$ gonako run test/type_test.nako3
  ok: タイプ1の名前は通常
  ok: タイプ1は3をFizzに変換する
  ok: タイプ1は15をFizzBuzzに変換する
  ok: タイプ2は3を数字のまま返す
  ok: タイプ2は15を数字のまま返す
  ok: タイプ3は3を数字のまま返す
  ok: タイプ3は5を数字のまま返す
  ok: タイプ3は15をFizzBuzzに変換する
  ok: 未定義のタイプはエラーになる
  9件成功、0件失敗
```

- `「…{番号}…」` は文字列の中に変数を埋め込む **文字列展開** です。
- `〜のエラー発生` は、その文字列をメッセージとする実行時エラーを起こします。`エラー監視` の外で起きれば、プログラムは `[実行時エラー]… 該当するタイプは存在しません: 4` と表示して終了コード 1 で止まります。
- 各分岐は `〜を戻す` で関数を抜けるので、`エラー発生` に到達するのは番号が 1〜3 以外のときだけです。

## 7.8 各言語のポリモーフィズム比較

| 概念 | なでしこ3 | Python | Prolog |
|------|-----------|--------|--------|
| 型の表現 | 関数を格納した辞書 | クラス（`abc.ABC` のサブクラス） | アトム `type_01` 等 |
| 多態の実現 | 辞書から関数を取り出して呼ぶ | メソッドのオーバーライド | 複数節ディスパッチ |
| 生成 | `タイプ生成`（番号→辞書） | `FizzBuzzType.create()` | `type_create/2` |
| 未定義タイプ | `エラー発生` | `raise ValueError` | `error(Message)` 項 |
| 契約の保証 | 実行時（`変換` キーを持つという約束） | 抽象メソッド（実行時） | 節の定義 |

## 7.9 まとめ

この章で学んだこと。

1. **関数を値として扱う**: `{関数}関数名` で関数を取り出し、辞書に格納できる。辞書が「オブジェクト」、格納した関数が「メソッド」の役割を果たす
2. **辞書によるディスパッチ**: `タイプ変換` は辞書の `変換` を呼ぶだけで、タイプを判定しない。条件分岐は `タイプ生成`（ファクトリ）に集め、変換ルールはタイプごとの関数に分けた
3. **識別子の制約**: ひらがなは助詞として区切られるため、`数字のみ変換` は `数字` と `み変換` に分割される。識別子は漢字・カタカナ・英数字で組み立てる
4. **エラー**: 未定義の番号では `エラー発生` で早めに失敗させ、テストでは `エラー監視` と `エラーメッセージ` で検証する

次の章では、この辞書と関数の組み合わせを使って、値オブジェクト・ファーストクラスコレクション・Command パターンを作ります。
